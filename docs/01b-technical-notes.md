## 2. Implementation gotchas (from the technical review)

1. **`_headers` merges matching rules.** A request inherits every matching rule, and duplicate header names are joined with commas. Two CSPs joined by a comma are two policies, and the browser enforces both.
   - For a per-route CSP, place the route rule after `/*`, unset the inherited header with `! Content-Security-Policy`, and then set the new one. The rule path is `/contact/`, because Astro uses directory format.
   - Add a test that asserts exactly one CSP header.
2. **Cache-Control merges the same way.** Set it only on `/_astro/*`. HTML already gets Cloudflare's revalidating default.
3. **Astro features that write inline code** and so must not be used:
   - Shiki highlighting (the default). Use `markdown.syntaxHighlight: 'prism'` with a self-hosted Prism theme instead.
   - The `<Code>` and `<Font>` components.
   - `transition:*` directives and framework islands (`client:*`).
   - `define:vars` and `is:inline`.
   - `check-dist.ts` scans the built HTML for `<script>` without `src`, any `<style>`, any `style=` attribute and any `on*=` attribute.
4. **Workers and Vite.** Vite only bundles a worker when the code contains the literal `new Worker(new URL(...), ...)` pattern. To use a Trusted Types policy:
   - import with `import url from './worker.ts?worker&url'`;
   - construct with `new Worker(policy.createScriptURL(url), { type: 'module' })`;
   - set `vite.worker.format: 'es'`;
   - feature-detect `self.trustedTypes`.
   Only `?worker&inline` produces `blob:` URLs, so `worker-src 'self'` is enough.
5. **Turnstile and Trusted Types.** Turnstile's `api.js` sets `script.src` from a string in its upgrade path, which throws under `require-trusted-types-for 'script'`. Leave Trusted Types out of the `/contact/` policy, and document why.
6. **404 when a Worker exists.** Use `assets: { not_found_handling: "404-page", run_worker_first: ["/api/*"] }` with a compatibility date of 2025-04-01 or later. The Worker's fallback is `env.ASSETS.fetch(request)`. Without this, non-navigation requests (curl, link checkers, Playwright `request`) reach the Worker instead of `404.html`.
7. **Release-age policy and fresh releases.** With `minimumReleaseAge: 10080`, Astro 7.3.8 (published 2026-10-08) is blocked until 2026-10-15. On 2026-10-09 the newest allowed version was 7.3.5.
   - Frozen installs re-check the lockfile against the policy.
   - For urgent security fixes, add a version-pinned `minimumReleaseAgeExclude` entry and record it in an ADR.
   - Dependabot's cooldown does not cover pnpm's check, and it does not apply to transitive dependencies.
8. **Tiers in tests.** Playwright enables software WebGL, so e2e and axe runs would get the 3D tier while Lighthouse CI gets the static tier. The frame-time downgrade would then trigger at random.
   - Use a tier override that exists only in non-production builds.
   - Run test projects for both tiers explicitly.
9. **Report-only CSP and Lighthouse.** Report-only violations fail `inspector-issues`. Test policies with e2e tests that fail on violations. Do not run report-only trials on previews that Lighthouse CI scores.
10. **Console checks.**
    - Lighthouse counts error-level messages only.
    - Our CI should fail on first-party errors, on CSP and Trusted Types violations, and on warnings that mention Permissions-Policy.
    - On `/contact/`, ignore messages from the Turnstile iframe in Playwright. Lighthouse does not see them.
11. **Email Sending onboarding is not needed.** Sending from the routing domain to a verified destination works without it. Onboarding would add its own DMARC record, which would conflict with ours.
12. **Fonts above the fold.** The document-control block uses the mono face, so all three upright files are preloaded (about 110 KB). Safari supports `size-adjust` but not `ascent-override`, so expect small metric differences there.
13. **Git history.** Commit with the GitHub noreply email. Never commit resume source files. CI runs exiftool on every PDF in `public/`.
